# 03 — Джобы: дайджест отзывов, аудит, контент-план

**Требования:** R08, R09, R12, R15i
**Зависит от:** 01
**Зона:** `team/jobs/` · `team/inbox/` · `.gitignore`
**Волна:** 2
**Ревью:** нет
**Модель:** обычная

## Что должно заработать

Скрипт `team/jobs/fetch-feedback.mjs` по SSH-алиасу `triptrek` читает новые отзывы
из прод-Postgres (READ ONLY) и складывает человекочитаемый дайджест в
`team/inbox/feedback/`. Рядом — runbook трёх джоб по расписанию (`team/jobs/README.md`:
дайджест ежедневно вечером, аудит по средам, контент-план по понедельникам; как
включить/изменить; что джоба делает и куда пишет) и чек-лист еженедельного аудита.
Сырые выгрузки не попадают в git.

## Из брифа, дословно

> «проверка и ответы на обратный отзывыв пользователей в приложении»
> «данные можешь собирать с прода, но только читать»
> «Проверку слабых мест»

(Решения владельца из раундов: «подключайся по ссш и читай данные оттуда что надо,
но только читай. Менять только по запросу»; расписание — «3. ок».)

## Разделы спецификации

spec.md: «Решение» (джобы, прод read-only), истории 8, 9, 11, 14, проработка
R08.1/R11.1/R12.1/R15i.1. Контракт скрипта, обезличивание, игнор raw/ —
`interfaces.md` (обязательно к прочтению первым). Модели Feedback/FeedbackMessage
и доступ до Postgres на VPS — `notes.md` §2–§3. Политики — `team/policies/`
(готовит T01; читать готовые).

## Критерии приёмки

- [ ] `bun team/jobs/fetch-feedback.mjs` — bun-скрипт без зависимостей; запросы зашиты в коде, только SELECT в READ ONLY транзакции (R12)
- [ ] Дайджест `team/inbox/feedback/YYYY-MM-DD.md`: id, тип, статус, дата, текст, контакт для ответа; сырой JSON — в `raw/`, и `team/inbox/feedback/raw/` добавлен в `.gitignore`
- [ ] Новых отзывов нет — файла нет, exit 0, stdout «новых отзывов нет» (R08.1)
- [ ] Сбой SSH/SQL — stderr + exit 1, без ретраев в обход (R11.1)
- [ ] `--since YYYY-MM-DD` переопределяет окно (по умолчанию 26 часов)
- [ ] Реальный прогон против прода прошёл и файл-дайджест создан (или зафиксировано «новых отзывов нет»)
- [ ] `team/jobs/README.md` — runbook: три джобы, расписание (вечер Минска, некруглые минуты), что каждая делает, что джобы создаются выключенными и включаются владельцем
- [ ] `team/jobs/audit-checklist.md` — чек-лист аудита: код, зависимости, тексты интерфейса, доступность, синк ролей (`sync --check`)
- [ ] Ни секретов, ни IP VPS в файлах; обезличивание соблюдено
