# Предложение правок в `AGENTS.md` (память проекта)

Дата: 2026-11-05. Источник: свежесобранная система-команда `team/` (ADR-0013,
ADR-0014). `AGENTS.md` принадлежит владельцу — автопилот в него не пишет,
ниже только предложения; применяет их владелец (сам или приказом агенту).

Проверено перед составлением: `docs/ai-team/` в репозитории нет (v1 лежит в
`docs/archive/ai-team-v1/`); `team/README.md`, `team/lifecycle.md`,
`team/jobs/README.md` на месте; `bun team/sync.mjs --check` — зелёно
(18 сгенерированных файлов); `bun team/jobs/fetch-feedback.mjs` — exit 0,
новых отзывов на проде сейчас нет. Подразделов «Правка без автопилота» и
«История git» в `AGENTS.md` нет. Bun на Windows-машине владельца в PATH
Git Bash не попадает — запуск как `"%APPDATA%\npm\bun"` (v1.3.14).

---

## Правка 1. Битые ссылки в шапке (строки ~8–9)

**Заменить:**

```markdown
Рабочий процесс продуктовой команды и роли агентов: [docs/ai-team/README.md](docs/ai-team/README.md);
запуск сквозного процесса — skill `/triptrek-team`.
```

**на:**

```markdown
Рабочий процесс продуктовой команды и роли агентов: [team/README.md](team/README.md)
(источник истины — папка `team/`; платформенные копии ролей генерируются из неё,
см. раздел «Система-команда» ниже). Прежняя версия — `docs/archive/ai-team-v1/`.
```

**Почему:** `docs/ai-team/` больше не существует — ссылка ведёт в никуда, а это
первое, что читает любой агент. Skill `/triptrek-team` относился к v1 и тоже
заархивирован.

## Правка 2. Строка `team/` в «Карту репозитория»

**Добавить в таблицу «Карта репозитория» строку (после строки `docs/`):**

```markdown
| `team/` | система-команда: роли, регламент (`lifecycle.md`), шаблоны, политики, джобы; источник истины, из которого генерируются `.claude/agents/`, `.github/agents/`, `.agents/skills/` (`bun team/sync.mjs`) |
```

**Почему:** карта репозитория — основной навигатор агента; без строки про
`team/` система-команда останется невидимой для следующих сессий.

## Правка 3. Новый раздел «Система-команда (team/)»

**Добавить новый раздел (предлагаемое место — сразу после «Карта репозитория»):**

```markdown
## Система-команда (team/)

Продуктовая работа (идея → разбор → спека → план → реализация → ревью →
релиз → измерение) ведётся системой-командой в `team/`: регламент —
`team/lifecycle.md`, роли — `team/roles/` (6 ролей: Стратег, Архитектор,
Инженер, Ревьюер, Рост, Поддержка + Координатор — основной агент диалога).
Правила: прод — только чтение (ADR-0014, `team/policies/prod-readonly.md`),
наружу — только черновики файлами, публикует владелец.

- Роли правятся только в `team/roles/`; платформенные копии
  (`.claude/agents/`, `.github/agents/`, `.agents/skills/`) генерируются и
  руками не правятся. После любой правки ролей: `bun team/sync.mjs`.
- Проверка целостности: `bun team/sync.mjs --check` — сейчас зелёно
  (18 сгенерированных файлов); в аудит слабых мест входит этот прогон.
- Джобы по расписанию (runbook — `team/jobs/README.md`): дайджест отзывов
  ежедневно 21:17, аудит слабых мест среда 21:41, контент-план понедельник
  21:23 (время по Минску, минуты намеренно некруглые). Результаты — файлами
  в `team/inbox/<джоба>/`.
- Отзывы с прода: `bun team/jobs/fetch-feedback.mjs [--since YYYY-MM-DD]` —
  READ ONLY через SSH-алиас `triptrek` (настройка — `team/policies/prod-readonly.md`);
  новых отзывов нет → exit 0 без файла, сбой SSH/SQL → exit 1 без ретраев.

На Windows-машине владельца `bun` не в PATH Git Bash — запускать как
`"%APPDATA%\npm\bun"` (v1.3.14).
```

**Почему:** агенту, открывшему проект, нужны точки входа и «красные линии»
системы (read-only прод, только черновики наружу, генерация вместо ручной
правки копий) — иначе он будет править сгенерированные файлы или искать
расписания по всему репо. Факт про bun вне PATH проверен болью на этой машине.

## Правка 4. Команды системы-команды в блок «Команды»

**Добавить в конец bash-блока «## Команды»:**

```bash
bun team/sync.mjs --check          # целостность ролей team/ (18 сгенерированных файлов)
bun team/jobs/fetch-feedback.mjs   # дайджест отзывов с прода (READ ONLY, SSH-алиас triptrek)
```

**Почему:** «Команды» — первый блок, куда агент смотрит за запускаемым;
проверка синка ролей должна быть на одном уровне видимости с lint/test.

## Правка 5. Подраздел «Правка без автопилота»

**Добавить раздел (по контракту памяти автопилота, адаптировано под то, что
реально лежит в `.autopilot/` — `PROGRESS.md` в проекте пока нет):**

```markdown
## Правка без автопилота

Мелкий баг или доводка после сборки — обычная сессия, без прогона.

Сначала прочитай:
1. `.autopilot/` — `dashboard.html` и `state.js` (прогресс и состояние сборок),
   `README.md` (как устроена папка).
2. Что правили после последней сборки — первая строка таблицы в «История git».
3. Только если правка их касается: почему сделано так — `docs/adr/`; что именно
   просили — `manifest.md` в папке сборки внутри `.autopilot/`.

После правки:
- коммит — по правилам из «История git»;
- договорились с владельцем о том, что следующая сборка не должна
  пересматривать, — зафиксируй его словами в заметках сборки (`.autopilot/`).
```

**Почему:** без этого подраздела сессия вне автопилота не знает, где лежит
контекст сборки, и оставляет коммиты, которые следующий прогон не сможет
отследить. Формулировки адаптированы: вместо отсутствующего `PROGRESS.md`
указаны реальные `dashboard.html`/`state.js`.

## Правка 6. Подраздел «История git»

**Добавить раздел (по контракту памяти автопилота):**

```markdown
## История git

Целиком не читай — бери срез под вопрос:

| Вопрос | Команда |
|---|---|
| что правили после последней сборки | `git log --oneline "$(git log -1 --format=%h --grep='^Autopilot: сборка сдана')"..HEAD -- . ':(exclude).autopilot'` |
| всё, что делали ради требования | `git log --oneline --grep="R02"` |
| история файла | `git log --oneline -10 -- <файл>` |
| когда появился или исчез код | `git log --oneline -S "<фрагмент>"` |
| почему строка такая | `git blame -L <с>,<по> <файл>`, затем `git show <sha>` |
| что внутри коммита | `git show --stat <sha>` |

Срез длиннее ~30 коммитов — отдай его субагенту и возьми выжимку в десять строк.

Коммит: заголовок — что (`fix: даты в одном формате`), тело — почему, трейлер
`--trailer "Requirements: R02"`, если правка касается требования из `manifest.md`.
Заголовок `Autopilot: сборка сдана` пишет только автопилот — по нему находят
последнюю сборку (если такого коммита ещё нет, первая команда таблицы вернёт
пустой срез — это нормально).
```

**Почему:** единый договор о срезах истории и формате коммитов делает правки
вне автопилота прослеживаемыми для следующего прогона; уточнение про пустой
срез — чтобы агент не считал его ошибкой на молодой истории.

## Правка 7. Актуализировать перечни ADR

**В строке таблицы «Карта репозитория» про `docs/` заменить**
`` `adr/0001–0011` `` **на** `` `adr/0001–0011, 0013, 0014` ``.

**В разделе «Прод» после** `` `0011` (донаты DonationAlerts: ...)`` **добавить:**
`, `0013` (система-команда `team/`), `0014` (прод — только чтение)`.

**Почему:** перечни ADR в AGENTS.md — точка входа в «почему так устроено»;
без 0013/0014 агент не найдёт решение о переходе на `team/` и политику
read-only прода из главного файла. ADR-0012 не существует — диапазон не
растягиваем.
