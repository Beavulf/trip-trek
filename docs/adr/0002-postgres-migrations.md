# ADR-0002: Postgres + prisma migrate

Статус: принято · 2026-09-09

## Контекст
SQLite — один писатель: конкурентная запись многих пользователей даёт `SQLITE_BUSY`. Деплой делал `prisma db push --accept-data-loss` на каждом старте — тихая потеря данных при конфликте схемы. Многошаговые операции (импорт поездки) не атомарны.

## Решение
Provider → `postgresql`, Postgres 16 в compose рядом с приложением. Схема — только через `prisma migrate` (`migrate deploy` в entrypoint); `db push --accept-data-loss` в деплое запрещён. Многошаговые записи — в `$transaction`. Прод стартует с пустой базой; перенос dev-данных — при желании через export/import.

## Последствия
- Managed-Postgres позже — стандартный переезд (тот же Prisma, другая DATABASE_URL).
- Файловая система не транзакционна: фото пишем до записи в БД с компенсирующим удалением.
