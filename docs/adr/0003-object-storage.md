# ADR-0003: Хранилище файлов — локальный диск в контейнере (самодостаточный стек)

Статус: принято · 2026-09-09 · **изменено владельцем 2026-09-10: S3 → локальный диск**

## Контекст
Фото — ключевой контент (99% пользователей — телефоны). Политика файлов
(EXIF/GPS, лимиты, сниффинг) была размазана по трём маршрутам и местами
отсутствовала — GPS с фото утекал в публичный URL.

Исходное решение (2026-09-09) предполагало S3-совместимое хранилище с первого
дня. Владелец изменил приоритет 2026-09-10: приложение должно быть
**самодостаточным** — подниматься на одном VPS одним `docker compose up` и
работать сразу, без внешних зависимостей.

## Решение
Один storage-модуль (`src/lib/storage/index.ts`): интерфейс `put/remove`,
единая политика внутри — magic-byte сниффинг, лимиты по kind (фото 20MB /
аватар 5MB / блюдо 10MB), UUID-имена, sharp-обработка (поворот по EXIF →
ресайз → jpeg; оригинал не сохраняется никогда, GPS выпиливается).

Файлы — на диске контейнера: том `triptrek-uploads` (/app/public/uploads),
раздаёт приложение (`server/static-uploads.ts`, immutable-кэш на год).
Модуль держитAdapter-шов внутри (единый `put/remove`), поэтому переезд на
S3 позже — это добавление второго adapter и env-флаг, без правки маршрутов.

## Последствия
- Плюсы: ноль внешних зависимостей, нет egress-стоимости и latency до bucket,
  простые бэкапы (tar тома рядом с pg_dump).
- Минусы/риски: фото привязаны к машине (переезд VPS = перенос тома); нет CDN —
  отдача ограничена каналом VPS; диск кончится без присмотра (см. мониторинг
  в DEPLOY.md); отказ диска = отказ фото (buckup.sh делает их внешний архив).
- Приватная раздача (проверка членства) — по-прежнему отложена; UUID-имена
  непредсказуемы.
