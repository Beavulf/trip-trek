# ADR-0005: Rate limiting — один модуль, store за швом

Статус: принято · 2026-09-09

## Контекст
Было четыре несвязанных in-memory лимитера (растущие Map без чистки), запись и аплоады не лимитированы вовсе, ключ — спуфаемый XFF без прокси-нормализации.

## Решение
Один модуль `limit(key, { max, windowMs })`; Store — внутренний шов: `MemoryStore` сейчас (с периодической чисткой), `RedisStore` при >1 инстансе. Ключ — `userId`, если известен, иначе IP из XFF (доверять только за Caddy). Единая таблица лимитов на все мутирующие и проксирующие маршруты (см. Phase 4 плана).

## Последствия
- Политика лимитов локализована в одном модуле и одной таблице.
- Переход на Redis — новый adapter, вызовы не меняются.
