# ADR-0007: Auth на запуск — e-mail+пароль, без SMTP/OAuth

Статус: принято · 2026-09-09 · **изменено 2026-10-22: SMTP-сброс реализован (`/api/auth/forgot-password` + nodemailer через постфикс-релей, TTL 60 мин); NextAuth удалён полностью — один путь выпуска JWT (custom-login)**

## Контекст
Аудитория ≤500 «своих» пользователей; инфраструктуры e-mail нет. Подключение SMTP/OAuth до запуска отодвигало бы деплой без пропорциональной пользы.

## Решение
На запуск: только существующая регистрация по e-mail+паролю (JWT 30d). Изначально зафиксировано: сброс пароля — вручную владельцем через БД; SMTP-сброс «поднимется позже», NextAuth-дубликат консолидировать при первом касании auth-кода.

## Поправка (2026-10-22)
Оба отложенных пункта выполнены:
- сброс пароля — самосервис: `/api/auth/forgot-password` (sha256-хеш в БД, TTL 60 мин), отправка через nodemailer → постфикс-релей на хосте (`SMTP_HOST=host.docker.internal:25`, см. DEPLOY.md §1/§6); ручной SQL-сброс больше не является нормой;
- NextAuth `[...nextauth]` удалён: единственный путь выпуска JWT — custom-login (`src/app/api/auth/custom-login/route.ts`).
ADR-0004 (handshake читает тот же JWT) по-прежнему в силе.

## Последствия
- JWT не отзывается до истечения: при компрометации — ждать 30 дней или ротация `NEXTAUTH_SECRET` (разлогинивает всех).
- SMTP/OAuth — отложенный скоуп, не отменяет решений ADR-0004 (handshake читает тот же JWT).
