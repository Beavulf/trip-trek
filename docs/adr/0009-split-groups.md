# ADR-0009: «Сочтёмся» — повседневные общие траты отдельными моделями

Статус: принято · 2026-10-23

## Контекст
Друзьям понравился расчёт долгов во вкладке «Бюджет», и они хотят вести так же повседневные траты (еда, аренда, коммуналка, интернет), а не только поездки. Бюджет поездки для этого не годится:
- привязан к `Trip` (даты старта, дни, лимит бесплатных поездок, переключатель поездок, достижения);
- суммы только в USD (`BASE_CURRENCY`, ADR-решение «модель A»), а повседневные траты — в местной валюте;
- нет правки траты и даты траты (только `createdAt`), деление только поровну, делёж лежит строкой `splitWith`;
- вышедший участник удаляется из `TripMember`, поэтому расчёт держится на подсистеме `people.ts` («бывшие»).

## Решение
1. **Отдельные модели `Split*`**, а не `Trip` с признаком вида: `SplitGroup`, `SplitMember`, `SplitExpense` + `SplitShare`, `SplitPayment`, `SplitRecurring`, `SplitActivity`. Поездки и их бюджет не трогаются; миграция только добавляет таблицы.
2. **Деньги — целые центы** (`Int`, `amountCents`). Долги и итоги считаются в ОДНОЙ валюте — валюте группы (`SplitGroup.currency`, выбирается при создании). Трату (и шаблон повтора) можно внести в другой валюте («аренда 500 $» в группе на Br): форма пересчитывает по курсу `/api/currency`, показывает курс и даёт поправить сумму в валюте группы вручную (реальный курс обмена у друзей не равен курсу API); в трату уходит пересчитанная сумма + введённое (`originalAmountCents`/`originalCurrency`, как в бюджете поездок). Долги остаются в валюте группы — отдельных долларовых балансов нет. Доля каждого хранится явно в `SplitShare.cents`, Σ долей = сумма траты (инвариант проверяет `normalizeExpenseInput`). Режимы деления: поровну, точные суммы, доли (веса), проценты; режим и веса хранятся, чтобы форму можно было открыть на правку.
3. **Участник — `SplitMember`**, расчёт ссылается на `SplitMember.id`, а не на `User.id`. Выход и исключение — мягкие (`status`), строка остаётся: история и долги вышедшего не пропадают, отдельной подсистемы «бывших» не нужно. `userId = null` — участник без аккаунта: его заводит любой участник, друг потом заходит по коду группы и выбирает «Это я» (`userId` проставляется, история остаётся).
4. **Перевод (`SplitPayment`) — отдельная сущность**, а не трата с магической категорией `settlement`. Записать «отдал» может любая сторона пары, второй приходит уведомление; идемпотентность — `clientKey`, уникальный в рамках группы. Перевод больше долга разрешён (получается встречный долг), UI предупреждает. Перевод можно привязать к трате (`expenseId`, SET NULL при удалении траты): это информационная отметка «доля закрыта», долги по-прежнему считаются попарным неттингом всех переводов.
5. **Права:** править и удалять траты, переводы и повторяющиеся шаблоны может любой активный участник; каждое действие пишется в `SplitActivity` (журнал изменений с диффом). Группу удаляет, исключает участников с аккаунтом и меняет валюту (пока нет трат) только владелец; название, значок и цвет правит любой. Безаккаунтного без истории (опечатка) может убрать любой.
6. **Расчёт долгов — попарный неттинг** (как в бюджете поездок): понятно «кто кому и из чего»; упрощение долгов в 3+ человека — потом.
7. **Повторяющиеся траты без cron:** шаблон `SplitRecurring` материализуется лениво — при чтении трат группы создаются недостающие периоды, идемпотентность — уникальный `(recurringId, recurringPeriod)`. Шаблон в иностранной валюте (аренда в долларах) хранит исходную сумму, и каждый период пересчитывается сервером по ЖИВОМУ курсу на момент создания записи (`fx-server.ts`, без статичного запасного списка: нет курсов — период не создаётся и ждёт следующего чтения). Курс на дату платежа не восстанавливается — API отдаёт только текущий; для точной суммы запись можно поправить вручную.
8. **Интеграция:** отдельный маршрут `/split` (хаб групп), `/split/[groupId]`, `/split/join` со своим layout (изумрудная тема через `<style>` на `:root/.dark`, порталы шитов наследуют её); оболочка поездки (`/`, 16 вкладок) не меняется — в ней только вход: пилюля в шапке, пункт меню «Ещё», карточка внизу вкладки «Бюджет». Свой `public/split.webmanifest` (раздел ставится на экран отдельным приложением, запуск сразу в форме траты — `start_url=/split/add`) + ярлыки в обоих манифестах (Android, долгое нажатие на иконку). **Быстрое добавление** (самое частое действие): последняя группа запоминается в cookie `triptrek-split-last` (`src/lib/split/last-group.ts`), `middleware` ведёт `/split` прямо в неё (хаб — `/split?all=1`, кнопка «назад» в группе); `/split/add` — группа с открытой формой БЕЗ редиректа (на iPhone «На экран Домой» сохраняет текущий адрес — иконка не должна привязаться к одной группе); в форме новой траты — переключатель группы. Realtime — комнаты `group:<id>` (тот же socket.io, `publishRoom`), пуши — персональные и только затронутым: новая трата → плательщику и тем, на кого делится; перевод → второй стороне (+ запись в колокольчик).
9. **Баланс считает клиент** (`src/lib/split/balances.ts`, чистые функции): мутации оптимистичны, и баланс обязан двигаться в тот же кадр, что и список. Хаб считает баланс группы SQL-агрегатами (5 запросов на любое число групп) — тот же результат, проверено интеграционным тестом.
10. **Удаление группы** — только через `deleteSplitGroup` с явным порядком: ссылки на участника намеренно без каскада (участника с историей нельзя удалить по ошибке), а Postgres каскадит дочерние таблицы в произвольном порядке (поймано интеграционным тестом на первом прогоне).
11. **Лимитов free-плана на раздел нет** (решение владельца 2026-10-23); техническая страховка от злоупотреблений — только rate limit и потолки размеров (участников, трат).

## Последствия
- Два параллельных движка долгов (бюджет поездки и «Сочтёмся»). Чистая математика денег живёт в `src/lib/split/`; перевод бюджета поездок на неё — отдельная задача, не сейчас.
- Участники без аккаунта открывают окно: код группы позволяет любому вошедшему «присвоить» безаккаунтную строку (выбор «Это я» обязателен, захват атомарный — побеждает один). Рассчитано на круг друзей, где код ходит в личных чатах; персональные токены на каждую строку — если понадобится.
- Долги в одной валюте (группы): расчёты между друзьями, которые возвращают долги в долларах, придётся вести вручную. Раздельные долларовые балансы (как в Splitwise) — отдельная большая задача, схема её не исключает.
- Фото чеков, экспорт, напоминания, упрощение долгов — вне v1, схема не мешает добавить их миграцией.
