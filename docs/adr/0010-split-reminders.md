# ADR-0010: Напоминания о долгах в «Сочтёмся»

Статус: принято · 2026-10-24

## Контекст
Раздел хорошо считает, кто кому должен, но долги закрываются только если должнику напомнили — а напоминать
вручную неловко. Друзья возвращают деньги картой или оплатой чего-то вместо денег (запись перевода с заметкой),
группы пока по 2–4 человека, возможны и больше. В приложении нет планировщика фоновых задач; единственный
инстанс на одном VPS (ADR-0001).

## Решение
1. **Ручное напоминание**: кредитор жмёт «Напомнить» в строке долга → `POST /api/split/groups/:id/remind`
   → уведомление должнику (колокольчик + пуш). Не чаще раза в 12 часов на пару. Должнику без аккаунта
   уведомление не отправить — клиент отдаёт готовый текст, чтобы переслать самому.
2. **Автонапоминание — настройка группы** `SplitGroup.remindAfterDays` (выкл / 3 / 7 / 14 дней, по умолчанию
   выкл, меняет владелец). Раз в час in-process таймер в `server.ts` (`startSplitReminderJob`) обходит такие
   группы. Напоминаем о долге, который существовал уже N дней: пара должна и сейчас, и была должна по записям,
   созданным до `now − N` (`dueAutoReminders`, чистая функция) — свежая трата вчерашний долг не «старит».
   Повтор — не чаще раза в N дней на пару; ручное напоминание тоже сбрасывает отсчёт. Шлём только в
   дневное окно (09–21 по Минску), долги меньше 1,00 игнорируем.
3. **История** — таблица `SplitReminder` (кто кого и когда; и для кулдауна, и для подписи «напомнили 3 ч назад»).
   Переживает рестарты, поэтому таймер идемпотентен.
4. **Реквизиты** остаются в `User.paymentDetails` (уже были); в пуш их не кладём — текст виден на экране
   блокировки. Их показывают экран долга и окно «Записать перевод».

## Последствия
- Планировщик в процессе: перезапуск контейнера пропускает час — не страшно (следующий тик догонит).
  Если инстансов станет больше одного (ADR-0001), нужен лидер/блокировка — шов: `runSplitReminders`.
- Напоминания идут только людям с аккаунтом и активным участникам.
- Отвергнуто: напоминать «по первому прочтению группы» (зависит от визитов), писать реквизиты в пуш,
  отдельные настройки для каждого должника (пока группы маленькие — избыточно).
