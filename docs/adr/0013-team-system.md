# ADR-0013: Система-команда в team/ с синхронизацией платформ

Статус: принято · 2026-11-05

## Контекст
«AI team» v1 была размазана по трём местам: роли в `.claude/agents/` и
`.github/agents/` (две текстуально одинаковые копии с разным frontmatter),
оркестратор в `.claude/skills/triptrek-team/`, регламент и политики в
`docs/ai-team/`. Копии ролей правились руками и могли расходиться; платформа Kimi
не была охвачена; состав ролей (5 штук) не покрывал поддержку пользователей и
аналитику текстов.

## Решение
Единый источник истины — `team/` внутри репозитория: роли (`team/roles/*.md` с
YAML-frontmatter `{name, description, tools}`), жизненный цикл (`lifecycle.md`),
шаблоны, политики доступа и джобы. Скрипт `team/sync.mjs` генерирует из источника
платформенные точки запуска для Claude Code (`.claude/agents/`), Copilot
(`.github/agents/`) и Kimi (`.agents/skills/`); сгенерированные файлы руками не
правятся, расхождение ловится `bun team/sync.mjs --check`. Состав ролей расширен
до шести: strategist, architect, engineer, reviewer, growth, support. v1 целиком
заархивирована через `git mv` в `docs/archive/ai-team-v1/` (история сохранена);
политики доступа переехали в `team/policies/` в обновлённом виде (SSH-алиас
`triptrek`, правило «менять только по запросу»).

## Последствия
- Правка роли делается один раз в `team/roles/`; платформы обновляются синком.
- Бриф и спека по привлечению остаются в архиве как входные материалы роли Рост.
- Старые ссылки на `docs/ai-team/` (в т.ч. в `AGENTS.md` владельца) ведут в архив
  и будут поправлены владельцем отдельно.
- Отвергнуто: три копии ролей вручную (расходятся), внешний сервис оркестрации
  (зависимость и секреты вне репозитория), автономные агенты-наблюдатели за
  файлами (платформа не поддерживает; вход — чат и джобы по расписанию).
