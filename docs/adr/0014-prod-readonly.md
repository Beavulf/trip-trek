# ADR-0014: Доступ к продy — только чтение через SSH и psql в транзакции READ ONLY

Статус: принято · 2026-11-05

## Контекст
Системе-команде нужны живые данные прода (прежде всего отзывы пользователей для
роли Поддержка), но слово владельца жёсткое: «данные можешь собирать с прода, но
только читать; менять только по запросу». Прод — один VPS с docker compose
(Postgres в контейнере), доступ по SSH уже настроен под алиасом `triptrek`.
Ошибка в доступе к проду дорога: откат случайной записи на живой базе владельца
дороже, чем неудобство от ограничений чтения.

## Решение
Скрипт `team/jobs/fetch-feedback.mjs` ходит по SSH-алиасу `triptrek` →
`docker exec triptrek-db psql` и выполняет выборку из таблиц `Feedback`/
`FeedbackMessage` внутри явной транзакции `BEGIN READ ONLY`. SQL-запросы зашиты
в коде скрипта; новая выборка — правка кода с ревью, а не параметр командной
строки, чтобы нельзя было «случайно» передать произвольный SQL. При сбое
SSH/SQL скрипт фиксирует ошибку и выходит с кодом 1 — без ретраев в обход и без
смены конфигурации. Сырые выгрузки не коммитятся в git. Любое изменение на проде
— только по отдельному явному запросу владельца; нарушение границы = стоп и
вопрос.

## Последствия
- Дисциплина чтения держится на двух уровнях: транзакция READ ONLY в psql и
  договорённость «только SELECT, зашитый в код». Технической преграды от root-
  доступа нет — есть регламент и проверяемый скрипт.
- Стоимость добавления новой выборки — коммит в скрипт, что осознанно замедляет
  расширение доступа и делает его видимым в истории git.
- Сбой прода/SSH не маскируется: дайджест просто не появляется, ошибка видна.

Отвергнуто:
- **Read-only роль PostgreSQL и SSH-профиль с ограниченными правами** (план из v1,
  `readonly-production-access.md`): правильнее технически, но требует изменений
  на самом проде — а по правилу владельца любые изменения на проде делаются
  только по его отдельному запросу. Отложено до такого запроса, не отменено.
- **API-эндпоинты прода для чтения отзывов**: требует писать и деплоить новый
  продуктовый код (тот же запрет на изменения прода), расширяет публичную
  поверхность и тянет авторизацию/лимиты — тяжелее и рискованнее прямого
  read-only SQL.
- **Передача SQL параметром командной строки**: превращает скрипт в универсальный
  исполнитель запросов на проде, ломая границу «только заревьюенные SELECT».
