# Доступ команды к данным

## Сейчас

| Источник | Наличие в проекте / разрешение | Рабочий доступ агента |
|---|---|---|
| Яндекс.Метрика | Счётчик и отправка целей из клиентского кода присутствуют (`src/lib/metrika.ts`) | Не подключён. Кабинет, токен и выгрузки агенту не предоставлены |
| Отзывы и обращения | Есть API и админ-интерфейс; сообщения и контактные данные хранятся в PostgreSQL | Не подключён к прод-данным. Можно анализировать код или предоставленный обезличенный экспорт |
| PostgreSQL на проде | Используется приложением | 05.11.2026 выполнена одна проверка агрегатов через root SSH по прямому указанию владельца; только `SELECT` внутри `READ ONLY` транзакции. Постоянный read-only доступ не настроен; root не является технически read-only и для дальнейшей аналитики не использовать |
| Серверные логи | Приложение развёрнуто на VPS | Рабочий доступ не настроен. Не передавать агенту SSH-ключи, env-файлы или неотфильтрованные логи |
| TikTok, YouTube Shorts, Instagram | Публичные профили указаны в [README.md](README.md) | Допустим только просмотр публичного содержимого; не входить в аккаунты и не публиковать |
| Почта | triptrek.team@gmail.com | Только контактный ориентир. Нет доступа к ящику; агент может подготовить черновик письма, но не отправлять его |

## Правила

- «Только чтение» означает техническое ограничение прав источника, а не только просьбу
  агенту. Одноразовое подключение 05.11.2026 было отдельным исключением по прямому
  указанию владельца: запросы были агрегатными и выполнялись в транзакциях `READ ONLY`,
  но root-доступ технически не ограничен чтением. Для дальнейшей работы использовать
  отдельную read-only роль и, по возможности, ограниченные представления с минимально
  необходимыми колонками.
- Не использовать и не выводить production-секреты, токены, пароли, cookie, адреса
  пользователей, содержимое личных поездок, фото, push-подписки или полный текст
  переписки без отдельного обоснования и согласованной процедуры.
- Для продуктовой аналитики предпочитать агрегаты, диапазоны дат и минимальные выборки.
  Не пытаться идентифицировать конкретных пользователей и не собирать лишние поля.
- Перед передачей обратной связи на анализ удалить email, имена, ссылки-приглашения,
  токены, точные координаты, имена поездок и другие идентификаторы. Скриншоты проверять
  на личные данные до передачи.
- Логи и аналитические выгрузки могут содержать персональные данные и секреты. Сначала
  отфильтровать и обезличить их локально; не загружать исходные дампы в сторонние
  сервисы/инструменты.
- Любое изменение/удаление данных, SQL кроме `SELECT`, отправка сообщения, изменение
  настроек кабинета или публикация требуют отдельного явного разрешения и не входят в
  полномочия аналитических ролей.

## Что нужно для подключения прод-аналитики

1. Уточнить нужные вопросы и метрики, а не запрашивать «всю базу».
2. Выбрать минимальный источник: агрегированный экспорт Метрики, ограниченное SQL-view
   или заранее очищенная выборка обратной связи.
3. Создать доступ с read-only правами и ограниченным сроком/объёмом данных; секреты
   хранить только в защищённом окружении, не в чате, тасках или git.
4. Проверить на небольшой обезличенной выборке; документировать поля, период и лимиты.
5. Удалять временные выгрузки после анализа и отражать выводы/неопределённость, а не
   сохранять персональные данные в отчётах.

Разовая агрегатная проверка не считается постоянным рабочим доступом. До создания
ограниченной роли/представлений регулярный доступ к production остаётся неподключённым.

Владелец сообщил, что доступен только обычный/root SSH-профиль; отдельный ограниченный
read-only профиль не настроен. Такой доступ не использовался. План безопасной проверки
воронки и настройки ограниченного доступа: [readonly-production-access.md](readonly-production-access.md).
