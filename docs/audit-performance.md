## Вердикт

Фундамент в хорошей форме: табы вынесены в `dynamic()`, WS-паблиши — дельты,
пароли/ключи клиенту не утекают, таймеры и objectURL чистятся, холодный старт —
5 HTTP-запросов. Блокирующих проблем нет.

Главные риски — не «первый заход», а **жизнь в поездке**: каждое событие
сотрудничества бьёт по двум тяжёлым read-model, загрузка фотографий множит это на
число файлов, а длинные списки (галерея/чат/дневник до 1000 записей) рендерятся
целиком с framer-motion на каждом элементе — на телефоне это секунды блокировки
потока. Плюс одна PII-утечка: email всех участников доступен каждому участнику.

## P0 — системные

1. **Инвалидационный шторм на фото.** `photo:added` публикуется на каждый файл
   (`api/photos/route.ts:112`), хендлер инвалидирует 5 семейств ключей
   (`use-websocket.ts:73-91`), локальные `onSuccess` дублируют те же ключи
   (`use-photos.ts:55-100`). Загрузка 10 фото = до ~10 волн × 4 тяжёлых GET
   (`photos`, `photos/geo`, `route`, `trip`). Фикс: debounce 300–500 мс на
   WS-инвалидации + не инвалилидировать в `onSuccess` то, что придёт по WS
   (глушить своё событие по `actorUserId`, как уже сделано для тостов).
2. **Двойной read-model.** `GET /api/trip` отдаёт participants + все days с местами +
   photos + expenses + journals (`api/trip/route.ts:22-34`), параллельно `GET /api/route`;
   `place:updated` инвалидирует оба (`use-websocket.ts:49-55`), `expense:added` — тоже.
   Каждое место/трата/запись = 2 тяжёлых GET с дублирующимся содержимым
   (замер: 25.7 + 20.8 KB на 45 мест). Фикс: сузить `/api/trip` до сводки
   (бейджи уже посчитаны сервером), дни читать только из `/api/route`.
3. **PII: email всех участников → каждому участнику.** `GET /api/trip` включает
   email в participants (подтверждено рантаймом), рендерится всем в «О поездке»
   (`member-manager.tsx:129`). Там же видны персональные бюджеты участников
   (`api/participants/route.ts:16-19`). Фикс: email — только в ответе для owner.
4. **Списки до 1000 записей без виртуализации.** Галерея — все фото, каждая плитка
   `motion.button` с mount-анимацией (`gallery.tsx:487-554`); чат — вся история,
   `MessageRow` не мемизирован и читает `localStorage` в теле рендера каждой строки
   (`board.tsx:620, 930`); журнал и лента — то же (`journal.tsx:561-580`,
   `timeline.tsx:551-575`). Любое WS-событие перерисовывает всё. Фикс: порционный
   рендер («показать ещё»/виртуализация), убрать motion с элементов списков,
   `React.memo` + localStorage наружу рендера.

## P1 — заметный эффект

5. **`/api/route` отдаёт лишнее**: встроенные `photos: { take: 8 }` каждого дня
   клиент не читает вообще (проверено грепом по `use-route`/`timeline`/`trip-map`),
   places — полными строками (18 полей, вкл. `createdAt/updatedAt`) —
   `api/route/route.ts:33-41`. Фикс: убрать photos, добавить select; полный текст
   места догружать точечно.
6. **Фото-API без пагинации**: `/api/photos` — до 1000 полных строк + лишний
   `include: { place: true }` (`api/photos/route.ts:24-35`); `/api/photos/geo` —
   вообще без `take` (`api/photos/geo/route.ts:14-27`).
7. **Фото-пины карты грузят оригиналы**, если нет миниатюры: пин и попап строятся
   из `photo.thumbUrl || photo.url` (`trip-map.tsx:397, 749`, `map/icons.ts:31-48`) —
   десятки полноформатных битмапов в памяти телефона. Фикс: бэкфилл thumbUrl,
   в пинах — только миниатюры.
8. **WS reconnect умирает насовсем**: `reconnectionAttempts: 10` × 2 с ≈ 20 с
   (`use-websocket.ts:32-34`). После сна/лагов realtime молчит до перезагрузки
   страницы. Фикс: бесконечный retry с backoff + `connect()` на `online`/focus.
9. **Первичный бандл** (386 KB gzip) можно ужать на ~50–60 KB gzip:
   exifr (~100 KB raw) попадает в первичку через статический `QuickAddSheet` →
   `PhotoForm` (`app-shell.tsx`, `quick-add/QuickAddSheet.tsx:9`) — обернуть в
   `dynamic()`; то же для оверлеев app-shell (`InviteFriends` с qrcode.react,
   `PremiumModal`, `ShareCard`, туры). Ленивые табы при этом работают правильно.
10. **Перерендеры бюджета**: `byCategory`/`dailyData` без `useMemo`
    (`budget/Budget.tsx:118-178`) — recharts перерисовывается при вводе трат.

## P2 — гигиена

- Уведомления: поллинг 30 с при живом WS, а WS-событие `notification` бейдж не
  инвалидирует (`use-notifications.ts:25`, `use-websocket.ts:202-233`) — realtime
  бейджа нет, зато есть постоянный трафик.
- `refetchOnWindowFocus: true` глобально (`providers.tsx:14`) — возврат в окно =
  до 5–6 GET, из них `trip` и `admin/stats` тяжёлые.
- PWA: минутный `setInterval(reg.update())` (`pwa-update.tsx:47-52`) — трафик/батарея;
  в `providers.tsx:24` листенер `load` не снимается и не регистрирует SW при
  клиентской навигации.
- Мёртвое: ключ `["days"]` инвалидируется в 11 местах при нулевом числе читателей
  (`query-keys.ts:19`), легаси `GET /api/days`, мёртвые deps (`@mdxeditor/editor`,
  `react-syntax-highlighter`, `@dnd-kit/*`, `@tanstack/react-table`, `embla`) —
  на бандл не влияют, но провоцируют случайные импорты и вес образа.
- `board:typing` вешается на сокет один раз и теряется при смене поездки
  (`board.tsx:346-357`) — функциональный баг индикатора «печатает».
- Прямые `fetch()` в компонентах в обход хуков: `member-manager.tsx:67`,
  `admin/UsersTab.tsx:97`, `admin/TripsTab.tsx:101`, `admin/SettingsTab.tsx:115,213`.
- recharts задвоен между `/` и `/admin` (два чанка по 388 KB raw) — лечится
  `splitChunks.cacheGroups` в `next.config.ts`.
- `exit`-пропсы в шторках — мёртвый код (условный маунт размонтирует до портала):
  анимации закрытия нет, риска зависших оверлеев нет.

## Проверено и чисто

- WS-паблиши — дельты/пустые объекты, полных объектов через шину не летает.
- `passwordHash` не сериализуется нигде; `aiApiKey` — только маска; админ-роль
  читается из БД; EXIF у фото срезается при загрузке.
- Таймеры, ResizeObserver, `URL.createObjectURL` (6 мест) — с очисткой/revoke;
  map-bus отписывается; WS cleanup (`trip:leave` + disconnect) корректный.
- Сжатие фото при загрузке mobile-safe (`createImageBitmap` + `close()`,
  `lib/image-compress.ts`); exifr — только лёгкий `gps()`.
- Zustand хранит только UI-состояние, persist партиализован.
- Локальный dev-сервер Postgres/запросы: N+1 не обнаружено.

## Порядок фиксов (по эффекту/затратам)

1. Debounce WS-инвалидаций + глушение своих событий (~1–2 ч) — убирает главный шторм.
2. Сузить `/api/trip` до сводки без days/places/expenses — каждое событие = 1 GET.
3. Срезка `/api/route` (photos, select) — минус 30–50% payload основного read-model.
4. Email участников только owner'у (~30 мин) — закрывает PII.
5. Галерея/чат: порционный рендер + memo + localStorage из рендера.
6. `dynamic()` для `PhotoForm`/`QuickAddSheet` и оверлеев app-shell.
7. WS reconnect без лимита попыток (одна строка).
8. Пагинация board/journal курсором (когда данные реально вырастут).
