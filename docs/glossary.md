# Глоссарий TripTrek

Зачем: в коде, UI и docs смешиваются русские и английские названия одних и тех же
сущностей. Это словарь соответствий, чтобы агент не тратил время на сопоставление.
Детали моделей — `prisma/schema.prisma`, архитектура — [architecture.md](architecture.md).

## Фичи главного экрана (табы SPA)

| В коде | В UI (рус.) | Что это |
|---|---|---|
| `dashboard` | Обзор | сводка поездки; после прошедшего `endDate` и до `completed` сверху — баннер-финал (`TripFinishedBanner.tsx`): незакрытые долги (расчет по cents-балансам) + «Закрыть долги →» в Бюджет + владельцу архивирование (PATCH status=completed); условие — `isTripFinished` (`trip-days.ts`) |
| **Зритель (viewer)** | read-only участник-друг: смотрит поездку (в т.ч. FAB скрыт), не мутирует (API отдаёт 403 «Вы зритель…»), слот free-лимита не занимает; роль переключает владелец кнопкой-глазом в «О поездке» |
| `timeline` | Лента | хронологическая лента событий/дней |
| **Карточки поездки (share)** | шит «Карточка поездки» (шапка): 6 canvas-вариантов — Сторис/Билет/Поляроид/Чек/Маршрут/**Итоги** (ночная сводка закрытой поездки: потрачено, города, состав, штамп «завершена», конфетти); живое превью, PNG и GIF-экспорт, приглашение и публичная страница (см. `/api/trip/share`) |
| **Публичная страница** | гостевой «живой журнал» поездки `/p/<shareToken>` (без входа): обложка со счётчиками и действиями (смотреть все фото — сразу лайтбокс всей галереи, ZIP, сердечко), плашка «Продолжить с того места» (последнее открытое фото или день, до которого долистал, — `localStorage` `triptrek:share-pos:<token>`, 30 дней; `lib/public-viewer.ts`), «Лучшие кадры» (избранное), главы-дни (текст+фото+места, кнопка «Смотреть · N»), вся галерея masonry **по дням** с заголовком дня; фото везде **по ходу поездки** — день ↑, время ↑ (раньше новые кадры шли первыми); лайтбокс YARL (свайпы/зум/подписи «День 3 · Шанхай · 5 из 24»/кнопки «к началу дня»/«следующий день»/скачивание/слайдшоу/полный экран/крестик); **слайдшоу** (кнопка в шапке: полный экран + автопереключение каждые 5 с, картинка вписывается в экран и увеличивается — горизонтальные кадры на всю ширину монитора; в конце альбома стоп) и тот же полный экран из кнопки в тулбаре; **карта по дням** (чипы «Все дни / Д1…»: места дня по порядку маршрута, линия, фото дня; тап по точке фото открывает его); **скрытие фото от гостей** (`Photo.hiddenFromPublic`: «⋯ → Скрыть от гостей» в приватной лайтбоксе, значок на плитке и фильтр в галерее) и **срок ссылки** (`Trip.shareExpiresAt`: 1/7/30/90 дней или бессрочно в окне «Поделиться»; после срока гости видят «срок закончился», продление возвращает ту же ссылку). Фото приходят двумя волнами: первая партия (200) — в SSR-пейлоаде, остальное гость докачивает порциями с `/p/<token>/photos` (счётчики — от общего числа в БД, не от загруженного списка); ZIP-архив — без потолка (zip64). Гостевые эндпоинты — `src/app/p/[token]/photos.zip`, `/photos` и `/heart` (лимиты по IP); включается владельцем из окна «О поездке» и кнопкой «Поделиться» в hero «Маршрута» и «Галереи» (`ShareTripSheet`: копирование, нативный «Поделиться…» через Web Share API с фолбэком в копирование, при выключенной ссылке — «Включить и поделиться»; данные — общий хук `usePublicShare`), там же тумблер «гости могут скачать фото» (`Trip.shareAllowDownload`) и rotate токена |
| **Лендинг** | открытая страница-презентация `/landing` для ссылки из TikTok (не таб SPA; `middleware` её не трогает, корень `/` у гостя по-прежнему ведёт на `/login`): `landing-view.tsx` + `landing.css`, картинки в `public/landing/`; главная кнопка → `/login?mode=register` («У меня есть код» при `inviteRequired`, «Войти» при закрытой регистрации; с `?code=XXXX` в адресе лендинга — «Создать аккаунт» и код подставляется в форму, так одна ссылка в профиле TikTok несёт код), «Живой пример» — публичная поездка из настроек (`demoTripToken` через `getPublicShowcase`), контакт — `contactTelegram`; Яндекс.Метрика — на лендинге и `/login` |
| `lodging` | Жильё | где ночуем: герой «Сегодня ночуем здесь» (или ближайшее заселение / итог), сводка (проживаний, ночей, стоимость), предупреждения о ночах без жилья и о пересечении дат, лента проживаний на «нити»; в карточке и герое — «Показать таксисту» (полноэкранно, `TaxiShowCard`), маршрут, звонок, копирование адреса; форма `LodgingSheet` (название на местном языке, даты, время, бронь, цена); зритель только читает (`src/components/trip/lodging/`, модель `Lodging`) |
| `itinerary` | Маршрут | план по дням: города, места, время; в hero у владельца кнопка «Поделиться» (публичная ссылка, см. «Публичная страница»), у остальных — ярлык «На карте»; полка «Жильё» (`lodging/LodgingStrip.tsx`) — карточки проживаний из вкладки «Жильё» (не из мест категории hotel): «сегодня ночуем здесь» первым, «Таксисту» и «Маршрут», ссылка «Все →» на вкладку; фильтр по дню показывает жильё этого дня (включая день выезда); без жилья полки нет, у закончившейся поездки она свёрнута; перетаскивание мест за «грип» меняет порядок внутри группы слота (утро/день/вечер, `Reorder` из framer-motion → `POST /api/places/reorder`); карточка места: навигация «← предыдущее / следующее →» по порядку обхода маршрута (`flatRoutePlaces`), правка точки на карте (MapPicker) в блоке редактирования |
| **PDF-экспорт маршрута** | кнопка в шапке вкладки «Маршрут» скачивает `GET /api/export/pdf` (pdf-lib, вшитый DejaVu из-за кириллицы): дни с городами/датами, места по слотам времени с адресом, бюджетом, описанием и заметками. Доступен всем участникам; билдер — чистая функция `src/lib/pdf/route-pdf.ts` (тесты в `route-pdf.test.ts`) |
| `map` | Карта | leaflet: места, фото с гео, маршрут; карта живёт между вкладками — строится при первом заходе и дальше прячется `display:none` (`mapEverOpened` в trip-store, проп `active` у `MapCanvas` гейтит полёты), возврат на вкладку мгновенный; фото-метки кластеризуются по экранной сетке и рисуются только в кадре (`map/photo-pins.tsx`, `src/lib/photo-pins.ts`) — иначе сотни миниатюр грузились и декодировались разом |
| `budget` | Бюджет | траты, делёж, долги + плановый бюджет; аналитика (категории/дни) с переключателем «Все / Моё / участник» — модель реальных денег (`calculatePersonalSpend` в `src/lib/budget/personal.ts`: общая трата целиком у плательщика; закрывается переводом или встречным зачётом — закрытая доля переходит к потребившему в категориях/днях исходной траты). Долги и балансы считаются в целых центах (`src/lib/budget/money.ts`: доли трат — методом старших остатков, Σ долей = сумма траты) — «Перевели» гасит пару ровно в ноль, без фантомных хвостов $0.01. «План по маршруту» (`budget/RoutePlanCard.tsx` + `calculatePlannedRoute` в `src/lib/budget/planned.ts`) — сворачиваемая сводка бюджетов, указанных в местах маршрута: итог поездки и на человека, факт по дням из трат, расшифровка по дням и по категориям мест; тот же план дня виден чипом в шапке дня на Маршруте. План маршрута также автоматически попадает в «План vs Факт» в группы категорий трат (`calculateRoutePlanByExpenseCategory`, маппинг место→трата) и складывается с ручным планом — правится только ручная часть, кнопка «К плану маршрута» сбрасывает ручные правки обратно. История трат — фильтры Все / Общие / Личные / Мои / Переводы; траты, внесённые до старта поездки, выделены секцией «До поездки · билеты и брони». В строках «кому сколько перевести» показываются реквизиты получателя (`paymentDetails` из профиля) с кнопкой «Копировать» — вместо номера карты в общий чат. История трат сгруппирована по дням с суммой дня (`budget/ExpenseList.tsx`, `lib/budget/history.ts`): новая строка плавно раскрывается, удалённая сворачивается; добавление/удаление траты и перевода — оптимистичные (`hooks/trip/use-expenses.ts`: строка видна сразу с пометкой «Сохраняется…», при ошибке откат). Во вкладке — скелетон вместо спиннера, личная сводка «Ты должен / Тебе должны» с подсветкой своих переводов, плавный счётчик суммы в шапке (`AnimatedNumber`, reduced-motion — без анимации), итог в центре бублика категорий. Форма «Новая трата» (`budget/AddExpenseForm.tsx`, аудит 2026-10-06; «Только я» одним тапом, описание по умолчанию — название категории, на кнопке — итоговая сумма в USD): поля по частоте (сумма → описание → категория-чипы → кто заплатил → за кого), «за кого» по умолчанию все, день по умолчанию текущий, sticky-submit |
| `gallery` | Галерея | фото (лайтбокс, избранное); masonry с `aspect-ratio` из `Photo.width/height`, порционный рендер по 60 (`gallery-tile.tsx`, плитки мемоизированы), лайтбокс YARL с мемоизированными слайдами и экономной предзагрузкой на слабой связи |
| `board` | Чат | групповой чат поездки (BoardMessage) |
| `journal` | Дневник | записи по дням с настроением (mood) |
| `food` | Гастрогид / Еда | блюда, «хочу попробовать», попытки; ИИ-шеф: «Подборка шефа» (пакет 4–10 блюд); «Рестораны рядом» при схлопе дублей переехал в Chill (`rest-chill/RestaurantsSheet.tsx`) |
| `phrases` | Разговорник | фразы (ru + локальный язык, транскрипция, озвучка); паки языков, фильтр «какой язык показывать» при 2+ языках |
| `info` | Справка | полезная инфа: визы, транспорт, сим-карты |
| `checklist` | Чек-лист | подготовка к поездке |
| `achievements` | Награды / бейджи | достижения по прогрессу (живые данные, не модель в БД) |
| `rest-chill` | Отдых / Чилл | категории отдыха (`chill-categories.ts`); «Рядом» — OSM-POI по геолокации + две ИИ-фичи: «Прогулка на ближайшие часы» — таймлайн из реальных мест, остановки добавляются в текущий день по одной; «Рестораны рядом» (`RestaurantsSheet.tsx`) — заведения OSM у города дня, ИИ отбирает шестёрку → в места дня (быстрый доступ — блок «Рядом · ИИ» в hero) |
| **Планер маршрута** | ИИ-подборка мест на выбор — не готовый маршрут (кнопка «Подобрать места с ИИ» в Маршруте): только существующие дни; пустой день — по «Пожеланиям», без них — лучшие места города; координаты — Nominatim по `nameEn` (`src/lib/geocode-place.ts`), `fail` → «уточнить на карте»; промпт получает координаты существующих мест дня как географический якорь (правило «рядом с отелем/районом»), после геокодинга выбросы получают `farWarning` «≈N км от остальных мест дня» (`markFarDrafts`, `src/lib/planner.ts`); в поездку — после явного «Добавить в маршрут» (`POST /api/places/batch`) |
| `weather` | Погода | Open-Meteo по городам дней |
| `ai-summary` | ИИ-итоги | саммари поездки от LLM |
| `template` | Шаблоны | готовые поездки (`trip-templates.ts`, «из шаблона») |
| `quick-add` | Быстрое добавление (FAB) | оранжевый FAB внизу экрана → шит с сегментом Фото/Трата/Заметка (`src/components/trip/quick-add/`). Фото — главный сценарий: геолокация запрашивается сразу при открытии формы (к съёмке координаты готовы; EXIF-GPS приоритетнее устройства, источник виден в чипе «Из фото»), сжатие не блокируется ожиданием гео, статус гео — чипом под превью; мультивыбор из галереи (ретро-кейс 2026-10: «50 фото за день по одной» убили фичу) уходит в экран-ревью `PhotoBatch`: кадры готовятся сразу, «Загрузить» доступна не дожидаясь всех, после нажатия шит закрывается, а загрузка идёт в **фоновой очереди** (`lib/upload-queue`, переживает закрытие шита, сворачивание и закрытие приложения; плашка прогресса над FAB, менеджер, полоса «Загружается» в галерее); дедуп: sha256 оригинала (`contentHash`) — уже загруженные кадры серые с плашкой «уже в поездке» и в очередь не идут, сервер страхует 409-ом `PhotoBatch.tsx`: день подбирается по дате съёмки из EXIF (`dayIdForDate`), ретрай упавших, один пуш друзьям на весь батч; submit-кнопки форм липкие внизу шита (`StickySubmit.tsx`). Трата и заметка — оптимистичные, с черновиками (точка на вкладке = есть неотправленное). Трата: поля по частоте (сумма → описание → категория → участники); категория — кнопка со списком поверх формы (`budget/CategoryField.tsx`, общая с формой на вкладке «Бюджет»), «за кого» по умолчанию только я (личная трата, без долгов), остальных отмечают осознанно; в поездке в одиночку блок «за кого» скрыт. Шит всегда смонтирован (open-проп), чанк PhotoForm прогревается на касании FAB; a11y: role=dialog, Esc, фокус-трап (`useDialogA11y`) |
| **Обратная связь** | окно «Обратная связь» (`components/trip/feedback/`: форма → «спасибо», «Мои обращения», переписка; `FeedbackSheet`). Пункты входа: меню «Ещё» (телефон), иконка в шапке (ПК), профиль, «Или просто напишите отзыв» в «Поддержать»; точка/бейдж «новый ответ» — `useFeedbackUnread`. Открывается из стора (`openFeedback(id?)`), ссылка уведомления `/?feedback=<id>`. Черновик текста — `useFormDraft`; сведения (вкладка, устройство, окно, версия, поездка) прикладываются по переключателю. Для гостей — `GuestContactSheet` на `/login` («Напишите нам»). Админка: `/admin/feedback` — список + панель на ПК / шторка на телефоне, поиск, быстрые ответы (`QUICK_REPLIES`), «Ответить и закрыть», заметка, сведения об отправке |

## «Сочтёмся» — повседневные траты друзей (отдельный раздел `/split`, не вкладка поездки)

Свой контур со своими моделями (ADR-0009): оболочка поездки `/` не затронута, переключение — «Сочтёмся» в шапке / меню «Ещё» / карточка внизу вкладки «Бюджет».
Экран — `src/components/split/`, данные — `src/hooks/split/`, чистая математика — `src/lib/split/`, API — `src/app/api/split/**`.

| Термин | Смысл |
|---|---|
| **Группа (SplitGroup)** | квартира/компания/пара; валюта группы, суммы в центах (траты можно вносить в другой валюте — «500 $» при группе на Br: пересчёт по курсу с ручной поправкой, долги всё равно в валюте группы); приглашение — короткий 8-символьный код `/split/join?code=` |
| **SplitMember** | участник группы; на него ссылаются траты и переводы (не на User). `userId = null` — «участник без аккаунта», его потом занимает друг («Это я»). Выход/исключение мягкие (`status` active/left/removed) |
| **SplitExpense / SplitShare** | трата и доли каждого в центах; режимы деления: поровну, точные суммы, доли (веса), проценты. Дата траты — календарный день, можно задним числом |
| **SplitPayment** | перевод «отдал деньги» между двумя участниками; записать может любая сторона, второй приходит уведомление; идемпотентен по `clientKey`. Может быть привязан к трате (`expenseId`): «за интернет перевёл» — в карточке траты у каждой доли видно «оплачено / осталось X» и кнопку «Перевёл(а)» / «Получил(а)» (`src/lib/split/expense-settle.ts`); в ленте фильтр «Должен(на) я». Перевод без привязки долю не закрывает, но снижает общий долг пары |
| **Повторяющаяся трата (SplitRecurring)** | шаблон «аренда 1-го числа»; траты создаются лениво при чтении группы, пауза при выходе участника из шаблона |
| **Напоминание (SplitReminder)** | «верни долг» должнику (ADR-0010). Вручную: кнопка «Напомнить» в «Балансе» у долга перед тобой, не чаще раза в 12 ч на пару; должнику без аккаунта — копируется готовый текст. Автоматически: настройка группы `remindAfterDays` (выкл/3/7/14 дней, владелец), часовой обход в `server.ts`, только днём по Минску, о долге старше срока (`dueAutoReminders` — по дате создания записей, а не траты). В уведомлении реквизитов нет. Реквизиты — `User.paymentDetails`: вводятся в «Ещё → Как вернуть мне деньги» или в профиле, должник видит их в долге и в окне «Записать перевод» |
| **Журнал (SplitActivity)** | кто что добавил/изменил/удалил (с диффом); править траты может любой участник, поэтому журнал обязателен |
| **Баланс / долги** | `memberBalances` (итог каждого, Σ = 0) и `pairDebts` (попарный неттинг, как в бюджете поездок) — `src/lib/split/balances.ts`; считает клиент |
| **Хаб** | `/split?all=1`: сводка «тебе должны / ты должен» по валютам + список групп; вкладки группы: Траты · Баланс · Итоги · Ещё. Обычный `/split` открывает ПОСЛЕДНЮЮ группу сразу (cookie `triptrek-split-last`, редирект в `middleware`; единственная группа — тоже сразу), хаб — по «назад» из группы |
| **Быстрая трата** | `/split/add`: последняя группа с уже открытой формой (адрес не редиректит — его кладут на экран «Домой»); в форме переключатель группы; `?add=1` на странице группы делает то же. Ярлыки «Новая трата» — в манифестах (`start_url` отдельного приложения = `/split/add`) |

## Доменные сущности

| Термин | Смысл |
|---|---|
| **Trip** (поездка) | центральная сущность; всё остальное каскадно висит на ней |
| **TripMember** (участник) | связь User↔Trip; роль `owner` (владелец) или `member`; свой `displayName`/emoji/цвет в рамках поездки |
| **Day** (день) | день поездки: `dayNumber`, город, `cityKey` (ключ города для погоды/координат) |
| **Place** (место) | точка маршрута: координаты, категория, `timeOfDay`, статус (`planned`→посещено, `visitedAt`), порядок `order` |
| **Expense** (трата) | `amount` в валюте поездки; введённое юзером — `originalAmount/`+`originalCurrency`; делёж `splitWith` (csv userId, пусто = личная) + `excludeSelf` |
| **Долг / settlement** | расчёт «кто кому сколько должен» (`src/lib/budget/`: split → balances → settle); переводы идемпотентны по `settlementKey`; считается по «участникам денег» (`people.ts`): вышедший/исключённый остаётся в долгах с пометкой «вышел», зритель вне денег (пока не фигурирует в тратах) |
| **BudgetPlan** | плановый бюджет по категории (уникален tripId+category) — не путать с расходами |
| **BoardMessage** | сообщение чата: реакции (JSON `{"👍":[userId]}`), ответы (`replyToId`), закрепление |
| **JournalEntry** | запись дневника (день + автор + mood) |
| **Phrase** | фраза разговорника; колонки `ru`/`cn`/`pinyin` исторические, язык — `language` (zh, ja, fr…) |
| **FoodItem** | блюдо гастрогида; голоса «хочу попробовать» — `wantedBy` (JSON-массив userId в строке) |
| **inviteCode** | код/ссылка приглашения в поездку (`/join/[code]`); участникам не отдаётся, если владелец включил «приглашает только владелец» (`Trip.allowMemberInvites`); не путать с «Инвайт-кодом приложения» (бета-доступ на регистрацию аккаунта) |
| **TripBan** | бан юзера в конкретной поездке (утёкшая инвайт-ссылка) |
| **currentDayNumber** | «сегодня N-й день поездки» — считать только через `src/lib/trip-days.ts` |
| **TimeOfDay** | слот времени места (morning/afternoon/evening) — порядок и подписи только через `src/lib/time-of-day.ts` |
| **Route (модель чтения)** | дни+места+мета поездки одним запросом: `GET /api/route` → хук `useRoute`/`useRouteDays`; селекторы — `src/lib/route.ts`. Не путать с вкладкой «Маршрут» (itinerary) |
| **PLACE_PATCHABLE** | единственный ручной список редактируемых полей Place (`src/lib/place-fields.ts`); POST/PATCH фильтруют тело через `pickPatchablePlace` — не добавляй параллельные белые списки |
| **TripTab** | активный таб SPA (zustand store `src/lib/trip-store.ts`, persist) |

## Пользователи, планы, ИИ

| Термин | Смысл |
|---|---|
| **User** | глобальный аккаунт (email, bcrypt, emoji/цвет/аватар) |
| **plan** | `free` / `premium`; премиум действителен пока не истёк `planExpiry`; проверка — только `isPremiumUser()` |
| **free-лимиты** | `freeTripLimit`, `freeMemberLimit` из `AppSettings` (настраивает админ) |
| **BYOK** | Bring Your Own Key: свой LLM-ключ юзера (`User.aiApiKey`), наружу только маска |
| **Полный BYOK** | свой ключ + свой `User.aiBaseUrl`/`aiModel`; инвариант `pickAiConfig` — юзерский адрес получает только юзерский ключ |
| **Цепочка ИИ-ключей** | юзер (BYOK) → админский в `AppSettings` → `env OPENAI_API_KEY` (`src/lib/ai-key.ts`). Режим беты — «только свои ключи»: общий не задан; тогда ключ юзера без своего адреса идёт на провайдера по умолчанию (OpenAI), а не на адрес из настроек админа. Без ключа вкладка AI показывает карточку «что это и где взять» (`ai-key-help.tsx`), статус — `GET /api/ai/status` |
| **aiBaseUrl / aiModel** | OpenAI-совместимый эндпоинт и модель (напр. `glm-4.6`): глобально — у `AppSettings`, свой уровень — у юзера (только вместе с его ключом) |
| **runAi / AI_FEATURES** | оркестратор всех ИИ-вызовов (`src/lib/ai.ts`): блок → лимит → ключ → провайдер → учёт; реестр фич с лимитами/температурами и швом премиум-гейта `access` — в `src/lib/ai-usage.ts` |
| **AiUsage** | учёт вызовов ИИ: юзер, фича, чей ключ (`keySource`), токены, длительность; промпты/ответы не пишутся. Пишет `runAi` fire-and-forget |
| **aiBlocked / алерты трат** | полный запрет ИИ юзеру (админ, `/admin/ai`); пороги `AppSettings.aiAlert*PerDay` — при превышении админы ловят уведомление (дедуп `aiAlertedAt` — раз в UTC-сутки) |
| **AppSettings** | singleton-строка `id="app"`: ключи ИИ + конфиг приложения; до записи — дефолты кода |
| **Инвайт-код приложения** | код бета-доступа на регистрацию аккаунта (модель `InviteCode`, выдаёт админ в `/admin/invites` → `/api/admin/invites`); при `inviteRequired` поле кода обязательно в регистрации; не путать с инвайт-кодом поездки (`Trip.inviteCode`), который даёт вход в конкретную поездку |
| **role** | `user` / `admin`; админ-роль всегда проверяется чтением из БД, не из токена |
| **AdminLog** | журнал действий админов (кто/что/когда; ключи и пароли в meta запрещены) |
| **Feedback** | обращение из приложения (баг/идея/вопрос/жалоба/отзыв) или гостя с `/login` (`userId=null`, `contactEmail`). Первое сообщение — `Feedback.message`, дальше переписка в `FeedbackMessage` (`author` user/admin). Статус = чья очередь: `new` — ждёт админа (новое или автор дописал, даже из закрытого), `in_progress`, `resolved`. `lastActivityAt` — сортировка очереди, `userSeenAt` — «непрочитанный ответ» у автора. Колонки `adminReply`/`repliedAt` устарели (миграция перенесла их в `FeedbackMessage`). Правила — `lib/feedback.ts` |
| **UserNotification** | колокольчик в шапке; типы: premium, password, member_removed, member_banned, trip_deleted, feedback_reply (ответ админа; ссылка `/?feedback=<id>` открывает окно), feedback_new (админам: новое обращение/реплика), split_payment, split_reminder («Сочтёмся»), admin_message, ownership |
| **PasswordResetToken** | одноразовый токен сброса; в БД только sha256-хеш, TTL 60 мин |
| **Обучение** | знакомство (по ролям: владелец / участник / зритель) + тур у каждой из 16 вкладок + «Сочтёмся» (хаб и группа); шаги с анимированными мини-макетами интерфейса и кнопкой «Попробовать»; список «Первые шаги» на Обзоре (отмечается сам по данным поездки); выход через панель «Закрыть обучение?» (продолжить / напомнить позже / пропустить тур / не показывать подсказки); кнопка «?» в шапке (на телефоне — «Ещё») открывает тур раздела; Центр обучения в Профиле (статусы, продолжить, сброс); прогресс на аккаунте — `User.onboardingState` (`src/components/trip/onboarding/`, `src/lib/onboarding*.ts`) |
| **Обновления** | «Что нового»: вторая вкладка окна колокольчика («Уведомления \| Обновления»); запись — карточка со списком, открывается с демо-макетом (шаги листаются руками), пунктами, кнопкой «Попробовать» и ссылкой на тур; непрочитанные — точка и счётчик на колокольчике, «прочитано» на аккаунте; записи — `src/lib/updates-content.ts`, компоненты `src/components/trip/updates/` |

## Инфраструктура и рантайм

| Термин | Смысл |
|---|---|
| **custom server / server.ts** | единый bun-процесс: Next HTTP + socket.io + `/uploads`; не «next start» |
| **ws-bus / publish()** | серверная шина realtime: API-роут → `publish(tripId, event)` → room trip-комнаты |
| **TripRooms / rooms** | серверный учёт «какой сокет в какой поездке» |
| **Очередь загрузки (upload queue)** | клиентская фоновая очередь фото: подготовленные кадры лежат в IndexedDB, отправляются по 3, ретраятся, ставятся на паузу при офлайне/429/401 и дошлются после перезапуска приложения; «черновик пачки» — выбор, который юзер ещё не отправил |
| **uploads / UPLOADS_ROOT** | файловое хранилище на диске (фото/аватары); в проде — докер-том `triptrek-uploads`; раздаётся мимо Next (`server/static-uploads.ts`) |
| **storage пайплайн** | `src/lib/storage/`: sharp-сжатие, превью, лимиты — единственный способ сохранять файлы |
| **outbound.ts** | обёртка внешних HTTP (таймаут+ретрай+кэш): Nominatim, Open-Meteo, курсы, LLM |
| **rate limits** | in-memory (`rate-limit.ts`): login 20/15мин/IP + 8 неудач/15мин/email, register 20/ч/IP, ИИ 10/ч/user+trip; обнуляются рестартом |
| **VAPID / web-push** | серверные пуши в браузер; ключи в env `VAPID_*` |
| **mailer** | nodemailer через постфикс-релей; `rejectUnauthorized: false` — только для самоподписанного серта локального релея |
| **Caddy** | обратный прокси на VPS: TLS Let's Encrypt, 80/443 → app:3000 |
| **standalone** | режим сборки Next (`output: "standalone"`); рантайм-файлы (uploads) в неё не попадают |
| **back-stack / useBackDismiss** | «назад» на телефоне закрывает верхний оверлей (шит/диалог/лайтбокс), а не сворачивает PWA: `src/lib/back-stack.ts` держит запись в history, пока оверлей открыт, popstate закрывает верхний; пустой стек — «назад» выходит из приложения как обычно |
| **ADR** | `docs/adr/0001–0008` — архитектурные решения и их мотивы |
| **worklog.md** | журнал сессий разработки: что менялось и зачем (история — искать здесь) |
