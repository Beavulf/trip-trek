# PDF-экспорт маршрута — Design Spec

**Date:** 2026-10-06
**Scope:** выгрузка маршрута поездки в PDF-файл одним кликом для офлайн-просмотра (скачал на телефон перед поездкой — открыл без сети).
**Out of scope:** бюджет/чек-лист/разговорник/гастрогид в PDF, фото, карта в PDF, print-страница (возможное дополнение позже).

---

## Решения (согласованы с владельцем)

| Вопрос | Решение |
|---|---|
| Состав PDF | Только маршрут: дни с городами/датами, места по слотам времени с адресами, описанием, заметками и бюджетом |
| Доступ | Все участники поездки. В отличие от JSON-бэкапа (`/api/export`, owner-only) здесь нет inviteCode и полного дампа — прятать нечего |
| Подход | Серверная генерация `pdf-lib`. Отклонены: print-страница (на телефоне/PWA диалог печати — ритуал из 4–5 шагов, файл не «скачивается»), `@react-pdf/renderer` (тяжёлая зависимость со своим reconciler'ом, болячки standalone-бандлинга, а шрифт с кириллицей всё равно регистрировать руками) |

## Goals

1. Кнопка на вкладке «Маршрут» → PDF-файл в загрузках одним нажатием.
2. Кириллица рендерится корректно везде (вшитый TTF-шрифт).
3. Генерация — чистая функция без БД, покрытая юнит-тестами.

## Non-goals

- Не включаем бюджет, чек-лист, фразы, гастрогид, фото, карту, статусы мест (planned/visited устареют сразу), rating и visitedAt.
- Не делаем брендированную вёрстку — аккуратный текстовый документ.
- Без rate-limit: генерация дешёвая, гард членства достаточен (JSON-экспорт тоже без лимита).
- Эмодзи категорий/слотов времени не рендерим — текстовые подписи: цветных эмодзи в PDF стандартно нет.

## Архитектура

### Зависимости

- `pdf-lib` + `@pdf-lib/fontkit` — чистый JS, без нативных модулей, работает под Bun.
- Шрифты: **DejaVu Sans** и **DejaVu Sans Bold** (TTF, пермиссивная лицензия, полный охват кириллицы) — в `src/lib/pdf/fonts/` вместе с файлом LICENSE. В выходной PDF встраивается subset, поэтому итоговый файл лёгкий.

### Изменения файлов

| Файл | Что делаем |
|---|---|
| `src/app/api/export/pdf/route.ts` *(новый)* | `GET ?tripId=`: гард `requireTripMember` (любая роль); выборка trip-меты + дней с местами — та же, что в `GET /api/route` (зеркалим select, комментарий-ссылка); пустой маршрут → 400 JSON; иначе `buildRoutePdf()` → ответ `application/pdf` с `Content-Disposition: attachment; filename="triptrek-route.pdf"; filename*=UTF-8''<название поездки>.pdf` |
| `src/lib/pdf/route-pdf.ts` *(новый)* | Чистый билдер `buildRoutePdf(input): Promise<Uint8Array>` — без БД/fetch; шрифты читает из `fonts/` рядом и кэширует в модуле |
| `src/lib/pdf/fonts/` *(новый)* | `DejaVuSans.ttf`, `DejaVuSans-Bold.ttf`, `LICENSE` |
| `src/components/trip/itinerary/Itinerary.tsx` | Кнопка `FileDown` (lucide) в шапке вкладки «Маршрут»; `fetch` → blob → скачивание (паттерн из `data-backup.tsx`), спиннер на кнопке, тост об ошибке |
| `next.config.ts` | `outputFileTracingIncludes: { "/api/export/pdf": ["./src/lib/pdf/fonts/**"] }` — шрифты попадают в standalone-сборку |
| Доки | `docs/api.md` (строка роута), `docs/glossary.md` (фича), `AGENTS.md` (модуль в карте репозитория), `worklog.md` — тем же коммитом |

### Контракт билдера

```ts
interface RoutePdfInput {
  title: string;        // trip.title
  destination: string;  // trip.destination
  currency: string;     // валюта поездки; символ — через общий хелпер валют
  startDate: string;
  endDate: string | null;
  days: Array<{
    dayNumber: number;
    date: string;
    city: string;
    title: string;
    summary: string | null;
    accentColor: string | null;
  places: RoutePdfPlace[]; // узкий структурный тип (name/category/timeOfDay/address/budget/description/notes);
                           // полный Place не подходит: prisma-строки дают Date, а не string.
                           // daySections обобщён под { timeOfDay } — см. src/lib/time-of-day.ts
  }>;
  generatedAt: Date;
}
```

## Содержимое PDF

- A4, поля ~48pt, основной текст 10–11pt, заголовки — Bold.
- Шапка (первая страница): название поездки, направление, даты («10.10 – 24.10.2026»), строка «Сгенерировано TripTrek, <дата>».
- Блок дня: «День N · <дата> · <Город>» + заголовок/саммари дня, если заполнены; тонкая цветная полоса-акцент слева блока (`accentColor` дня, fallback — фирменный оранжевый).
- Места группируются по слотам **переиспользуемой** чистой функцией `daySections()` из `src/lib/time-of-day.ts` (Утро / День / Вечер / Без времени) — не дублируем логику.
- Место:
  - название — жирным;
  - строка-мета: категория текстом из `CATEGORY_SHORT` («Кафе», «Храм»), адрес (если есть), бюджет места с символом валюты (если задан);
  - описание (`description`) и заметки (`notes`) отдельными абзацами, если заполнены.
- Перенос страниц: блок дня не рвётся посередине — если не влезает, целиком уходит на новую страницу; если блок больше страницы, режем между местами.
- Колонтитул: «стр. N из M» внизу по центру.

## Обработка ошибок

- Пустой маршрут (0 дней или 0 мест) → 400 `{ "error": "Маршрут пуст — добавь дни и места" }`, на клиенте тост.
- Сбой генерации → 500 + запись в `logger.error`, тост «Не удалось сформировать PDF».
- Скачивание с теми же credentials (cookie JWT), что остальные запросы клиента.

## Тестирование

`src/lib/pdf/route-pdf.test.ts` (vitest, node-env):

1. Выход начинается с магических байтов `%PDF` и валиден (`PDFDocument.load` не падает).
2. Мало данных → 1 страница; 40+ дней → страниц больше одной (счёт через `PDFDocument.load(...).getPageCount()`).
3. Кириллица, длинные заметки (перенос строк), пустые опциональные поля — не падают.
4. День без мест всё равно рендерит заголовок блока.

Ручная проверка: скачивание из мобильного PWA (iOS Safari, Android Chrome), открытие офлайн, кириллица.

## Риски

- Шрифты не попадут в standalone-сборку → страхуемся `outputFileTracingIncludes` и ручной проверкой docker-сборки.
- Кириллица в `Content-Disposition` → RFC 5987 (`filename*`), ASCII-fallback `triptrek-route.pdf`.
- Длинные заметки без переносов разорвут строку → у билдера свой word-wrap по ширине колонки (в pdf-lib нет автоматического).
