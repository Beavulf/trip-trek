# Бета-запуск TripTrek: инвайт-коды, лендинг, метрика

Дата: 2026-10-23 · Статус: согласовано с владельцем (brainstorming-сессия)
Цель: выпустить приложение для ограниченной публичной беты — трафик из короткого
видео в TikTok, первые пользователи тыкают приложение и оставляют отзывы через
встроенный фидбек. Оценка готовности на момент сессии: фидбек, админка, лимиты
free, PWA, rate limits, бэкапы — уже в проде; не хватает контролируемого доступа,
точки входа для трафика и измеримой воронки.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Механика доступа | Инвайт-коды (не open registration, не waitlist-заявки) |
| Точка входа для трафика | Отдельная страница-презентация `/landing` (ссылка из TikTok), с блоком «Возможности» и живым демо; `/` и `/login` для гостя не меняются |
| Аналитика | Яндекс.Метрика на лендинге и `/login` (env-флаг, в dev off) |
| Верификация email | Не делаем в бете (~500 чел; пересмотреть после) |
| Captcha / waitlist / оплата | Не делаем (rate limit + код достаточно; waitlist добавим, если кодов не хватит) |

## 1. Инвайт-коды в приложение

### Модель данных (prisma/schema.prisma)

```prisma
model InviteCode {
  id            String    @id @default(cuid())
  code          String    @unique // 6–8 символов A-Z0-9 без O/0/I/1
  note          String? // «тикток-видео», «для Лехи» — только для админа
  maxUses       Int       @default(1) // ≤ 1000
  usedCount     Int       @default(0)
  expiresAt     DateTime?
  deactivatedAt DateTime?
  createdAt     DateTime  @default(now())
  createdBy     String
  users         User[] // «кто пришёл» — для справки в админке
}

model User {
  // …существующие поля…
  inviteCodeId String?
  inviteCode   InviteCode? @relation(fields: [inviteCodeId], references: [id], onDelete: SetNull)
}
```

Авторитетный счётчик активаций — хранимый `usedCount`; связь с `User` — только
справочная. Удаления кодов нет (в API только деактивация), поэтому рассинхрон
не accumulate'ится.

Занятие слота — атомарно и гонко-безопасно, без транзакционной обвязки:

```ts
const res = await prisma.inviteCode.updateMany({
  where: {
    code, deactivatedAt: null,
    OR: [{ expiresAt: null }, { expiresAt: { gt: new Date() } }],
    usedCount: { lt: maxUses },
  },
  data: { usedCount: { increment: 1 } },
});
if (res.count === 0) return 400 «Код недействителен или все места заняты»;
```

Новый модуль `src/lib/invite-code.ts`: генерация кода (`crypto`, алфавит без
похожих символов), нормализация ввода (`trim().toUpperCase()` — как у инвайт-кодов
поездок), чистый предикат «код активен» для отображения статуса в списке.
Юнит-тесты рядом (`src/lib/invite-code.test.ts`).

### Флаги и правила регистрации

В `AppSettings` новые поля (singleton, редактируются в админке «Настройки»):

- `inviteRequired: Boolean @default(false)` — регистрация требует код;
- `demoTripToken: String?` — токен публичной поездки для лендинга (§2);
- `contactTelegram: String?` — «@name» или ссылка, показывается на лендинге и `/login`.

Матрица регистрации (`POST /api/auth/register`):

| `registrationEnabled` | `inviteRequired` | Поведение |
|---|---|---|
| false | — | 403 «регистрация временно закрыта» (как сейчас) |
| true | false | как сейчас, код не спрашиваем |
| true | true | код обязателен: существует → активен по `invite-code.ts` → иначе 400 с текстом «Код недействителен или все места заняты» |

Порядок регистрации с кодом: атомарный условный инкремент `usedCount` (см. выше)
→ создание юзера с `inviteCodeId`. Rate limit поднят с 3 до 20/ч/IP (мобильный трафик за общим IP оператора); приветственное
письмо — как сейчас.

### Публичный эндпоинт для формы

`GET /api/auth/register-options` (публичный, rate limit 60/мин/IP — форма логина
дёргает его на каждом заходе):
`{ registrationEnabled: boolean, inviteRequired: boolean }`. Страница `/login`
по нему решает: показывать ли поле «Инвайт-код» и режим регистрации.

### Админка

Новая вкладка «Инвайты» (`src/components/admin/`):

- генерация пачки: количество кодов, активаций на код (`maxUses`), срок действия
  (или бессрочно), note;
- список: код (клик = копировать), активировано X/Y, срок, note, статус
  (активен / истёк / деактивирован / места исчерпаны), кнопка «Деактивировать».

API (все под `requireAdmin` + запись в `AdminLog`):

- `GET /api/admin/invites` — список с хранимыми `usedCount`, сортировка по `createdAt`;
- `POST /api/admin/invites` — `{ count ≤ 100, maxUses, expiresAt?, note? }` → созданные коды;
- `PATCH /api/admin/invites/[id]` — `{ deactivatedAt: Date | null }` (только вкл/выкл).

Оба сценария TikTok поддерживаются сразу: один общий код с `maxUses = 100`
(«код в описании») или пачка персональных кодов для «первых N».

## 2. Лендинг на triptrek.com/landing

### Механика

Лендинг — отдельная публичная страница `/landing`, презентация приложения. Корень
не трогаем: гость на `/` по-прежнему получает редирект на `/login` (вышел из
аккаунта — видит форму входа, а не рекламу). `src/middleware.ts` не меняется:
`/landing` не входит в его matcher, поэтому открыта всем, в том числе вошедшим.
Ссылка для био/описания TikTok — `triptrek.com/landing`.

Скриншоты кладём в `public/landing/` (владелец снимет; до этого — плейсхолдеры).

### Состав (server component, без бэкенда)

1. **Hero**: заголовок + 1–2 строки («Планируйте маршрут, бюджет и общий альбом
   вместе — всё в одном месте»), кнопки «Начать планирование» →
   `/login?mode=register` и «У меня есть код» → `/login?mode=register&invite=1`
   (фокус на поле кода), скриншот в рамке телефона.
2. **Возможности** — 6 блоков «картинка + текст», чтобы было видно, на что
   способно приложение:
   - Маршрут по дням: места, время, жильё, нити маршрута на карте;
   - ИИ-планер: черновик маршрута из реальных мест (не выдумок) — подтверждение
     юзером перед добавлением;
   - Бюджет: общие траты, «кто кому сколько должен», любые валюты;
   - Галерея и дневник: фото грузятся в фоне, переживают закрытие приложения;
   - Вместе в реальном времени: чат, пуши, приглашение в поездку кодом;
   - В поездке: гастрогид, разговорник с ИИ, погода, достижения.
3. **Живой пример**: ссылка на реальную публичную поездку
   `/p/<demoTripToken>` («Вот так выглядит настоящая поездка»); секция
   скрывается, если `demoTripToken` не задан.
4. **Плашка «Бета»**: «Приложение в бете — могут быть шероховатости. Внутри
   есть кнопка „Сообщить о баге“, мы читаем всё».
5. **Футер**: контакт `contactTelegram` («Вопросы — напишите нам»), одна строка
   о данных («Фото чистятся от геометок, пароли хранятся только в виде хешей»).
6. **OG-теги**: title/description/og-image (картинка уже в `public/`) — чтобы
   ссылка в TikTok разворачивалась в карточку.

Лендинг — server component и читает `AppSettings` напрямую: кнопка «У меня есть
код» показывается только при включённом `inviteRequired`, иначе в ней нет смысла.

## 3. Вспомогательное

- **Яндекс.Метрика**: env `NEXT_PUBLIC_YANDEX_METRIKA_ID`; скрипт на `/landing`
  и `/login`; без env — не подключается вовсе. Воронка «видео → визит →
  регистрация»; регистрации в разрезе кодов видны в админке («Инвайты»).
- **Футер `/login`**: «Застряли? Напишите нам: {contactTelegram}» — сигнал от
  тех, кто не смог войти.
- **SMTP-проверка перед анонсом** (чеклист, не код): сброс пароля письмом должен
  реально работать на проде — пункт в `docker-deploy/DEPLOY.md`.

## 4. Сознательно не делаем

Верификация email · captcha · waitlist-заявки · Sentry/GA · оплата и
selfUpgrade-флоу · мобильные натив-приложения.

## 5. Чеклист запуска (после реализации)

1. Сгенерировать коды под кампанию в админке (например, `TIKTOK26` на 100 мест).
2. Выложить 1–2 реальные поездки публичными («Поделиться» → тумблер), токен
   демо — в «Настройки» админки.
3. Проверить на проде: регистрация с кодом, без кода (отлуп), сброс пароля
   письмом, лендинг `/landing` по ссылке из био TikTok, `/` гостем уходит на логин, OG-превью ссылки.
4. Включить `inviteRequired`.
5. Метрика подключена, событие регистрации видно.
6. Видео + ссылки (лендинг, код) в описании.
