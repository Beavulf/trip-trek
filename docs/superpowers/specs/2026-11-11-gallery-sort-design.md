# Сортировка фото в галерее («сначала старые ↔ сначала новые»)

Дата: 2026-11-11
Статус: принято

## Задача

Во вкладке «Галерея» порядок всегда «сначала новые» — он задан на сервере
(`orderBy: { takenAt: "desc" }` в `src/app/api/photos/route.ts`). Пользователи
хотят просматривать кадры с начала дня (при фильтре по дню) или с начала всей
поездки (без фильтра).

## Решение

- Переключатель порядка — иконка-кнопка в верхнем ряду фильтр-бара, справа от
  звезды и кнопки сетки (размещение по решению владельца 2026-11-11; первая
  версия была чипом с подписью в линейке чипов — подпись состояния унесена в
  aria-label/title). Активное состояние («Сначала старые») подсвечивается
  primary-тоном, иконка меняет направление.
- Клиентская сортировка: API и так отдаёт весь список поездки одним запросом
  (takenAt desc); «сначала старые» — разворот массива в `useMemo`. Без новых
  запросов, кэш-ключей и сравнения дат — таймзоны не затрагиваются.
- Порядок применяется к сетке (masonry/compact) и лайтбоксу — листание идёт
  в выбранном порядке. Лента «Недавние кадры» в шапке всегда «сначала новые».
- Тап по кадру «Недавних» открывает фото по id в упорядоченном массиве:
  в режиме «сначала старые» индексы ленты и ленты лайтбокса не совпадают.
- Переключение сбрасывает порционный рендер (`filterKey` включает порядок —
  иначе после нескольких «Показать ещё» реверс тащит в DOM сотни плиток) и
  закрывает лайтбокс (контент массива сменился, как у остальных фильтров).
- Выбор запоминается в localStorage `triptrek-gallery-sort` — глобальная
  настройка вида, не по-поездочная (префикс как у `lib/currency-pref.ts`).
  Чтение — ленивый инициализатор `useState`, запись — прямо в обработчике,
  без эффекта.
- Кнопка «Сбросить» порядок не трогает: она про фильтры, а не про вид.

## Альтернативы (отклонены)

- Серверный `?order=asc|desc` в `/api/photos`: «канонично», но каждый тап —
  рефетч всей ленты (сотни записей), плюс два кэш-ключа на поездку.
- Сортировка на слое хука `usePhotos`: тот же результат, но state вида уезжает
  от остальных фильтров галереи.

## Изменения

- `src/components/trip/gallery.tsx` — единственная содержательная правка
  (тип порядка, хранилище, memo, чип, лайтбокс). API, схема и хуки не меняются.
- Доки: строка галереи в `docs/glossary.md`, запись в `worklog.md`.

## Тесты

Логики сортировки как таковой нет (разворот готового массива, компаратор не
пишется) — юнит-тест не требуется. Проверка: lint, существующие тесты, ручная
проверка UI в браузере (порядок сетки, лайтбокса, ленты «Недавние», запоминание).
