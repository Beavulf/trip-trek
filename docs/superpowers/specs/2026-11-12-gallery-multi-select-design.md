# Мультивыбор фото в галерее

Дата: 2026-11-12
Статус: принят (владелец: «давай спеку, дальше план реализации и делай»)
Предыстория: аудит UI галереи 2026-11-11–12 (полировка фильтр-бара — `18733be`);
мультивыбор назван главным функциональным пробелом — все действия сейчас только
по одному кадру через лайтбокс.

## Задача

Выбрать пачку кадров на вкладке «Галерея» и применить действие разом:
избранное, скрытие от гостей, удаление. Поездки на сотни кадров требуют этого
постоянно (ретро-кейс владельца: «разобрать сотню кадров по одному — боль»).

## Права (уже на сервере, не меняем API)

- `PATCH /api/photos/:id` и `DELETE /api/photos/:id` — `requireTripEditor`:
  зритель получает 403 → **режим выбора зрителям не показывается вовсе**.
- Избранное и скрытие — любой не-зритель на любой кадр.
- Удаление — автор кадра или владелец поездки (`403 «Можно удалять только свои
  фото»`). Пачкой у не-владельца: удаляются только свои, чужие пропускаются —
  подтверждение честно показывает расклад, тост-итог называет пропущенные.

## Вход и выход

- **Долгое нажатие** (~500 мс) на плитку (masonry и compact): таймер на
  pointerdown, отмена при pointerup/scroll; срабатывание — вибро-хаптика
  (в духе волны 2), режим включается, кадр уже выбран. Лайтбокс при этом не
  открывается (открытие — только на коротком тапе без сработавшего таймера).
- Кнопка **«Выбрать»** (иконка `SquareCheck`) — первой в кластере иконок
  фильтр-бара, перед звездой.
- Выход: «Готово» в панели действий; `useBackDismiss(selectMode, exit)` —
  «назад» на телефоне закрывает режим, не сворачивая PWA.

## В режиме выбора

- Тап по плитке — toggle выбора; на плитке появляется чекбокс-уголок
  (поверх, существующие значки избранного/автора/скрытости остаются).
- Фильтры, чипы, сортировка и сетка работают как обычно; выбор хранится по
  `photo.id`, поэтому пропавшие из выборки кадры остаются выбранными, счётчик
  панели считает только кадры, видимые в текущей выборке? — **нет**: счётчик
  считает всё выбранное (выбор не теряется при смене чипа), а действия
  применяются ко всему выбранному.
- «Выбрать все» — добавляет все кадры текущей выборки; «Снять всё» — очищает.

## Панель действий

Липкая снизу над FAB (в стиле плашки прогресса загрузки): «Выбрано N» +
кнопки:
- **В избранное / Убрать из избранного** — динамическая подпись: все
  выбранные уже в избранном → предлагаем обратное;
- **Скрыть от гостей / Показать гостям** — аналогично по `hiddenFromPublic`;
- **Удалить** — AlertDialog «Удалить N фото?»; у не-владельца дополнительно
  «Будут удалены ваши кадры: M, чужие будут пропущены»; M=0 — кнопка
  недоступна.
- «Готово» — выходит из режима.

## Мутации

Существующими роутами, без нового API: последовательные вызовы с ограниченной
параллельностью (4), `Promise.allSettled`; оптимистичного кэша нет — после
завершения инвалидация `["photos"]`/`["photos-geo"]`/route-данных (как у
одиночных мутаций) + тост-итог («Готово 12 · не удалось 1»). Каждый вызов
сервера шлёт свои realtime-события — другие клиенты обновятся штатно.
