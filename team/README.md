# Команда TripTrek

Система-команда для разработки и развития TripTrek: принимает задачу прямо в чате
и ведёт её по всем этапам — от разбора идеи до релиза, измерения и ответов на
отзывы. Эта папка — **единственный источник истины**: роли, регламент, шаблоны и
политики правятся только здесь.

Техническая карта продукта остаётся в [AGENTS.md](../AGENTS.md) — её читает любая
роль перед работой с кодом.

## Начни отсюда

Чтобы поставить команде задачу, просто напиши её сообщением в чат — например:
«хочу добавить экспорт маршрута в PDF для попутчиков» или «разбери свежие отзывы».
Дальше координатор (основной агент диалога) сам регистрирует задачу файлом в
`team/inbox/`, определяет роль и ведёт работу по этапам из
[lifecycle.md](lifecycle.md), спрашивая тебя только в важных развилках.

Пример диалога:

> **Ден:** Придумал фичу — офлайн-разговорник по категориям поездки.
> **Координатор:** Зарегистрировал идею в `team/inbox/ideas/<дата>-<slug>.md`.
> Передаю Стратегу: разберёт проблему, аудиторию, сильные/слабые стороны и риски.
> **Стратег:** …готов бриф. Слабое место: офлайн-наборы уже есть, ценность — в привязке
> к маршруту. Открытый вопрос тебе: делаем для всех или это премиум-фича?
> **Ден:** Для всех.
> **Координатор:** Бриф дополнен. Готовлю спеку с Архитектором — покажу на одобрение
> перед реализацией.

## Роли

| Роль | Файл | Ответственность |
|---|---|---|
| Координатор | основной агент диалога | Регистрирует задачу, определяет роль, передаёт субагенту, ведёт этапы и приёмку |
| Стратег | [roles/strategist.md](roles/strategist.md) | Разбор идей: проблема, аудитория, сильные/слабые стороны, риски, метрики успеха |
| Архитектор | [roles/architect.md](roles/architect.md) | Спецификация, план тасков с зависимостями, ADR при смене соглашений |
| Инженер | [roles/engineer.md](roles/engineer.md) | Реализация одобренных тасков: код, тесты, доки тем же коммитом |
| Ревьюер | [roles/reviewer.md](roles/reviewer.md) | Независимое ревью изменений и еженедельный аудит слабых мест |
| Рост | [roles/growth.md](roles/growth.md) | Стратегия продвижения, контент-план недели, черновики постов |
| Поддержка | [roles/support.md](roles/support.md) | Отзывы пользователей, черновики ответов, аналитика текстов |

## Что где лежит

- [lifecycle.md](lifecycle.md) — этапы конвейера и точки, где система спрашивает владельца.
- `roles/` — промпты ролей (источник истины; платформенные копии генерируются).
- `policies/` — [доступ к данным](policies/data-access.md) и
  [read-only доступ к проду](policies/prod-readonly.md).
- `templates/` — шаблоны: бриф идеи, спека, таск, релиз, разбор обратной связи.
- `strategy.md` — стратегия продвижения (ведёт роль Рост).
- `inbox/` — результаты работы: разборы идей, дайджесты отзывов, аудиты, контент-планы.
- `jobs/` — джобы по расписанию и их runbook.

## Правила

- Прод — только чтение (SSH-алиас `triptrek`, запросы в транзакции `READ ONLY`).
  Любое изменение на проде — отдельный явный запрос владельца.
- Наружу система не отправляет ничего: ни постов, ни ответов пользователям, ни писем —
  только черновики файлами; публикует и отправляет владелец.
- Секретов здесь нет и быть не должно: ни ключей, ни паролей, ни значений из `.env`.
- Сырые выгрузки отзывов (`team/inbox/feedback/raw/`) в git не коммитятся.

## Синхронизация платформ

Роли правятся один раз — в `team/roles/`. Команда `bun team/sync.mjs` генерирует
платформенные точки запуска (Claude Code, Copilot, Kimi); сгенерированные файлы
руками не правятся. Проверка расхождения: `bun team/sync.mjs --check`.

Предыдущая версия системы (v1) заархивирована в
[docs/archive/ai-team-v1/](../docs/archive/ai-team-v1/), решение — в
[ADR-0013](../docs/adr/0013-team-system.md).
