# Джобы по расписанию

Три джобы работают без участия владельца (R15i). Джобы — это крон-задачи Kimi Work
(local_conversation) в этом проекте. Создаются **выключенными**; включает их
владелец — кликом по карточке задачи или просьбой агенту. Наружу джобы ничего
не отправляют: результат — всегда файл в `team/inbox/<джоба>/` + сообщение в чат.

Все расписания — вечер по Минску, минуты намеренно некруглые (R15i.1), чтобы не
попадать в пиковые «ровные» минуты планировщика.

## Три джобы

| Джоба | Расписание (Минск) | Что делает | Куда пишет |
|---|---|---|---|
| Дайджест отзывов | ежедневно, 21:17 | Запускает `bun team/jobs/fetch-feedback.mjs`, при наличии новых отзывов сообщает в чат и передаёт дайджест роли Поддержки | `team/inbox/feedback/YYYY-MM-DD.md` (+ сырой JSON в `raw/`, в git не коммитится) |
| Аудит слабых мест | среда, 21:41 | Роль Ревьюера проходит чек-лист `team/jobs/audit-checklist.md`: код, зависимости, тексты интерфейса, доступность, синк ролей | `team/inbox/audit/YYYY-MM-DD.md` |
| Контент-план | понедельник, 21:23 | Роль Роста готовит контент-план недели из `team/strategy.md` и черновики постов (публикация — за владельцем) | `team/inbox/content/YYYY-MM-DD.md` |

## Дайджест отзывов: детали

Скрипт `fetch-feedback.mjs` ходит в прод **только на чтение**: SSH-алиас
`triptrek` → `docker exec triptrek-db psql`, один `SELECT` по `Feedback`
(+ `LEFT JOIN "User"` ради отображаемого имени) внутри транзакции `READ ONLY`.
Запросы зашиты в коде; новая выборка — правкой скрипта через таск с ревью,
не параметром запуска (R12.1). Политика — `team/policies/prod-readonly.md`.

- Ручной запуск: `bun team/jobs/fetch-feedback.mjs [--since YYYY-MM-DD]`.
  Без флага — окно последних 26 часов (вечерний запуск захватывает вчерашний
  вечер); `--since` задаёт начало окна как 00:00 указанной даты по Минску.
- Новых отзывов нет — файл не создаётся, скрипт печатает «новых отзывов нет»
  и завершается с кодом 0 (R08.1): джоба в этот день молчит.
- Сбой SSH/SQL — сообщение в stderr и exit 1, без ретраев в обход и без смены
  конфигурации (R11.1). Разбор — владельцем.
- Обезличивание: в дайджесте — id, тип, статус, дата, текст и способ связи;
  email и имена — только в `raw/` и только если есть в записи.

## Как включить, изменить или выключить джобу

- Включить/выключить: клик по карточке задачи в Kimi Work или просьба агенту
  («включи джобу дайджеста»). После включения проверьте время следующего
  срабатывания на карточке — оно должно совпадать с таблицей выше.
- Изменить расписание: попросить агента («перенеси аудит на четверг 20:12») —
  минуты держим некруглыми, вечер по Минску.
- Разовый прогон вне расписания: «запусти джобу дайджеста сейчас» — расписание
  от этого не включается и не меняется.
- Изменить, что джоба делает (другая выборка, другой формат): это правка кода
  или роли — обычный таск через конвейер с ревью, не настройка расписания.
